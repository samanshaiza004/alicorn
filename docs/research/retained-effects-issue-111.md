# Bounded retained effects — issue #111

2026-11-03 research; status update 2026-11-04. Read [issue #111](https://github.com/samanshaiza004/alicorn/issues/111) directly. The original note below records the pre-implementation decision and source review; the implementation outcome now lives in the [validation report](../validation/issue-111-retained-effects.md). Upstream wiki and `main` links below are rolling references observed on 2026-11-03; validate against the actual SDL revision used by the implementation.

**Original recommendation:** GO for a small, explicitly enabled probe; NO-GO for shipping a general effects layer on synthetic evidence alone. Start with one isolated paint boundary and retained identity composition, then an alpha-mask shadow. Treat backdrop blur as a separate, more expensive input-capture problem. This was a pre-implementation recommendation, not the current shipping decision.

**Implementation status (2026-11-04):** the [validation report](../validation/issue-111-retained-effects.md) now documents a supported `backdrop_blur` semantic-surface API, a fence-tracked SDL_GPU Gaussian compositor, deferred-effect retry, and Scratchpad Quick Open as its first ordinary consumer. The user reviewed the Gaussian presentation and approved using it. This supersedes the original NO-GO decision for the narrow bounded blur capability; it does not promote a general effects graph or claim unverified Windows/D3D12 acceptance.

## What the primary sources establish

- [PanGui's September update](https://pangui.io/blog/07-progress-update-september/#render-effects) reports arbitrary-content render effects, platform-specific support, and precompiled/custom effects. It also explicitly says many ordinary shape/text glows and shadows need no separate render effect. It supplies no Alicorn-relevant memory, idle, invalidation, or cross-backend performance evidence.
- [Skia `GrBlurUtils.cpp`](https://github.com/google/skia/blob/main/src/gpu/ganesh/GrBlurUtils.cpp), especially `draw_shape_with_mask_filter` and `ComputeBlurredRRectParams`, tries direct filtering before mask construction and supports compact rounded-rectangle masks/nine-patch geometry. Compare analytic rounded-rect/SDF coverage or a cached mask before allocating a component-sized color surface. Those techniques do not reproduce blur of arbitrary pixels behind a palette.
- [Firefox's WebRender overview](https://firefox-source-docs.mozilla.org/gfx/RenderingOverview.html#rendertask-tree) describes rasterization, optional downscaling, horizontal/vertical Gaussian passes, and composition, with ping-pong targets and cached outputs. This supports a small ordered pass chain; it does not establish that Alicorn needs a render graph.
- [Chromium's `SkiaRenderer`](https://github.com/chromium/chromium/blob/main/components/viz/service/display/skia_renderer.cc), in `IsSufficientForRequirements`, checks size, format, alpha type, and color space before backing reuse; `UpdateRenderPassTextures` removes obsolete/incompatible backings. Its backdrop code separately calculates input/output bounds and clipping. Reuse compatibility and capture bounds deserve explicit contracts even in a much smaller compositor.

## Required boundary and SDL_GPU rules

These are proposed experiment constraints, not claims about Alicorn's present architecture.

| Area | Smallest defensible contract |
| --- | --- |
| Boundary and invalidation | Identify a resolved generic paint range, stable boundary ID, source paint/resource generations, device generation, transform/DPI, clips, parameters, input extent, and output extent. Reuse only when all relevant inputs match. Image/glyph uploads must invalidate even if paint commands are unchanged. Initially repaint the whole bounded surface on any input change; defer partial updates. |
| Halo and clips | Convert to physical pixels once; round bounds outward. Use the actual finite kernel support, plus shadow offset/spread, to expand capture/output. A proposed Gaussian truncation is `ceil(3*sigma)` per axis, explicitly an approximation. Distinguish source clipping from clipping the final effect: preclipping everything to the final panel rectangle cuts off blur input/shadow tails. Specify transparent exterior for isolated masks and a deliberate backdrop edge policy. [Filter-region padding](https://www.w3.org/TR/filter-effects-1/#FilterRegion) is established precedent. |
| Creation and sampling | Use single-sample 2D textures with `COLOR_TARGET \| SAMPLER`; query the exact format/type/usage combination. SDL fragment samplers cannot read multisample textures. Precompile shaders for supported backends. See [usage flags](https://wiki.libsdl.org/SDL3/SDL_GPUTextureUsageFlags), [format support](https://wiki.libsdl.org/SDL3/SDL_GPUTextureSupportsFormat), and [sampler restrictions](https://wiki.libsdl.org/SDL3/SDL_BindGPUFragmentSamplers). |
| Pass order | End the source pass before filtering; use distinct input/output textures for each blur pass, then composite at the original painter-order position. No in-place sampling of the destination. Rebind graphics state/viewport/scissor after each pass. SDL prohibits overlapping render/copy/compute passes; its [overview](https://wiki.libsdl.org/SDL3/CategoryGPU) also notes state reset and pass cost. Current [SDL validation source](https://github.com/libsdl-org/SDL/blob/main/src/gpu/SDL_gpu.c) has the broad sampler/target-alias check disabled for advanced cases: absence of a debug assertion is no proof of safety. |
| Initialization and retention | Transparent-clear new/dirty targets and `STORE` every output needed later. Use `LOAD` only for initialized retained contents. `DONT_CARE` is safe only with guaranteed complete overwrite, including padding. See [render-pass rules](https://wiki.libsdl.org/SDL3/SDL_BeginGPURenderPass) and [load/store operations](https://wiki.libsdl.org/SDL3/SDL_GPUColorTargetInfo). |
| Backdrop input | SDL [swapchain textures are write-only](https://wiki.libsdl.org/SDL3/SDL_WaitAndAcquireGPUSwapchainTexture): neither sampling nor copying them as a read source is permitted. Capture the already-resolved paint prefix into a bounded owned texture, with the same background and clips, before drawing the palette/foreground. Include underlying paint changes in its generation. If replay cannot reproduce that prefix, defer backdrop blur; do not silently redirect every ordinary frame through a full-window target. |

For alpha, use one documented representation throughout capture/filter/composition: premultiplied RGB and alpha; clear to `(0,0,0,0)`; blur all four channels together. For source-over, `out.rgb = src.rgb + dst.rgb*(1-src.a)` and likewise for alpha: use `ONE, ONE_MINUS_SRC_ALPHA` for both channels. Applying `SRC_ALPHA` again darkens retained edges. Group opacity scales RGB and alpha together. These follow [Porter–Duff source-over](https://www.w3.org/TR/compositing-1/#porterduffcompositingoperators_srcover); [filter primitives](https://www.w3.org/TR/filter-effects-1/#FilterPrimitivesOverview) generally operate on premultiplied samples, while some color operations require temporary unpremultiplication.

Color space is a separate decision. SDL's [SDR swapchain](https://wiki.libsdl.org/SDL3/SDL_GPUSwapchainComposition) contains sRGB-encoded values in a non-sRGB format; `SDR_LINEAR` uses an sRGB format with linear shader access. An offscreen UNORM target does not automatically make color linear. Prefer linear-light color filtering, with explicit ingress/egress conversion consistent with the existing renderer. If existing data is premultiplied in encoded space, decode straight RGB before premultiplying in linear space; decoding the premultiplied channels directly is wrong. Start with alpha-only shadow filtering to avoid making a global color-pipeline change a prerequisite. A zero-effect retained round trip must preserve current output. SVG filter primitives default to linearRGB, whereas CSS filter functions use sRGB: [the standard distinguishes them](https://www.w3.org/TR/filter-effects-1/#ColorInterpolationFiltersProperty), so browser appearance alone is not a color oracle.

## Lifetime, budget, fallback, and idle

- **Pool backing storage, not validity.** Key reusable allocations by device generation, size class, format, usage and sample count; keep content validity separately. Bound live, pooled, in-flight, and retiring bytes together. Example probe limits: one active boundary, no nesting, at most 1024×1024 physical pixels including halo, `sigma <= 8` physical pixels, three offscreen stages (source, horizontal, vertical) plus main composition, and a 32 MiB requested-texel budget. Count any main-pass split too. Three RGBA8 targets at that size consume 12 MiB before extra in-flight versions; RGBA16F doubles it. These are proposed limits, not measured safe defaults or exact driver residency figures.
- **Avoid hidden budget growth.** SDL [cycling](https://wiki.libsdl.org/SDL3/CategoryGPU#a-note-on-cycling) can allocate another internal resource when all versions are bound, and makes subsequent contents undefined. For an auditable probe, use a fixed fence-tracked target pool with `cycle=false`, reuse only completed slots, and choose the plain fallback rather than allocating/blocking when exhausted. A partial retained update cannot rely on cycling preserving pixels. Measure driver allocation/residency separately from logical texture bytes.
- **Retire safely.** Remove evicted/resized entries from lookup immediately. [SDL_ReleaseGPUTexture](https://wiki.libsdl.org/SDL3/SDL_ReleaseGPUTexture) defers freeing until safe; never reference the released handle again. Fences are needed for deliberate pool reuse/accounting, not a prerequisite to SDL's safe release. Keep retiring storage charged conservatively until completion; avoid resize storms creating unlimited replacement targets.
- **Fail before capture where possible.** Unsupported format, missing pipeline, budget exhaustion or allocation failure selects ordinary paint/analytic shadow/opaque palette, with original order and clips. [Texture creation](https://wiki.libsdl.org/SDL3/SDL_CreateGPUTexture) can fail, and [submission](https://wiki.libsdl.org/SDL3/SDL_SubmitGPUCommandBuffer) can fail too. Never publish a failed generation as valid. Device failure invalidates every GPU cache generation; flat drawing on that same failed device is not recovery. Hand off to host device recreation or its existing failure path; do not promise transparent recovery from these APIs. SDL's [Vulkan submission source](https://github.com/libsdl-org/SDL/blob/main/src/gpu/vulkan/SDL_gpu_vulkan.c) distinguishes swapchain/surface recreation from queue-submission errors.
- **Make absence cheap.** With no enabled boundaries, keep the current direct frame path: no effect pool/pipeline initialization, pass, upload, fence, allocation, or new per-node retained state. When static effects settle, schedule no polling, wake, frame or submission. A later unrelated repaint may composite a valid cached result without refiltering. Check pool fences during naturally occurring work, and evict on events/budget pressure rather than a cleanup timer. SDL explicitly recommends minimizing passes and resource churn in its [performance guidance](https://wiki.libsdl.org/SDL3/CategoryGPU#performance-considerations).

## Original proposed experiment and acceptance evidence (historical)

1. **Prove the boundary:** one opt-in, unnested resolved paint range; one retained identity target; full invalidation on change. Preserve clipping, painter order, DPI and zero-effect pixels. No public effect graph or layout/node semantics changes.
2. **Prove one effect:** source alpha/mask → horizontal blur → vertical blur → tinted shadow behind ordinary content. Disable blending in overwrite filter passes; source-over only at composition. Compare the same interaction against analytic geometry/SDF or a cached mask. Then evaluate one palette backdrop capture using the bounded paint prefix. These are candidate dogfood cases, not confirmed consumer requirements.
3. **Decide with matched traces:** baseline, best cheap alternative, and retained candidate; same release build/toolchain, content, viewport/DPI and input trace. Record cold first-frame and warm CPU/GPU p95, pass count, upload bytes, live/peak/retiring texture bytes, driver memory, allocation churn, binary size and implementation size. Separate GPU timing from CPU submission timing and readback stalls. Establish absolute frame/memory budgets on the intended hardware before running; a relative percentage alone can hide expensive small scenes.

Readback is test-only: render to an owned texture, end rendering, download in a copy pass, submit with a fence, wait successfully, then map/read using the transfer row layout and release the fence. Downloads are not complete before fence signaling. See [download](https://wiki.libsdl.org/SDL3/SDL_DownloadFromGPUTexture), [fenced submission](https://wiki.libsdl.org/SDL3/SDL_SubmitGPUCommandBufferAndAcquireFence), [wait errors](https://wiki.libsdl.org/SDL3/SDL_WaitForGPUFences), and [row layout](https://wiki.libsdl.org/SDL3/SDL_GPUTextureTransferInfo). Do not read the swapchain or add production readbacks.

Required fixtures: transparent colored edges over black/white/checkerboard; overlapping translucent content/group opacity; impulse and constant-alpha masks against a CPU kernel reference; zero-radius identity; halo/offset and nested clips; fractional DPI; source/image-generation changes; parameter changes/removal; resize/reopen; pool exhaustion; injected creation/submission failure and device-generation reset. Compare cached output with a fresh repaint. Fix tolerances and kernel/edge conventions in advance; distinguish exact alpha/composition checks from backend AA variation. Reuse #90/#104 capture infrastructure if suitable, without treating their scope as completed here.

**GO for adoption only when** two named real app interactions visibly and materially beat the cheaper alternatives; measured cold/warm costs fit the agreed budgets; repeated resize/open/close stays bounded; failure paths never show stale pixels; no-effect control and return to true idle remain unchanged; and readback/native evidence covers Metal, Vulkan, D3D12 plus a lower-power/integrated baseline where accessible. Record unavailable backends as unverified, not passed.

**NO-GO/defer** if analytic geometry/cached masks suffice, only one interaction benefits, backdrop capture requires mandatory whole-window composition, correctness depends on undefined contents/aliasing, memory grows with cycling/in-flight work, the color contract is unresolved, or static scenes acquire new work. No runtime/GPU measurements, native consumer comparisons, or device-loss recovery tests were performed for this note; this is permission to investigate, not evidence to ship.
