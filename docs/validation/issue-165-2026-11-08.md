# Issue #165 — headless semantic UI driving and capture

Validated on Windows on 2026-11-08 against Alicorn `1d238ed` plus this
follow-up. Odin was `dev-2026-11-nightly:9a69916`; the History native host
reported SDL 3.4.18 and Direct3D12.

## Headless harness and replay

The public `alicorn:testui` harness now reports semantic IDs for focus and
pointer targets, semantic revisions, causal ID/kind/action, and per-turn
retained-work deltas. Bounded JSON replay logs support up to 256 turns, a
1 MiB encoded artifact, and 64 KiB of explicitly opted-in text. User text is
redacted by default; a recording that omitted required text refuses playback.
Replay checks target/focus identity, revision, cause, stabilization, and,
optionally, exact same-build work counters.

The replay tests record a semantic button interaction, encode/decode it, and
replay it through a fresh runtime. A changed semantic target is detected
before activation. Text tests verify default redaction, refusal to replay
missing payloads, and faithful playback only when text capture is explicitly
enabled. Existing harness coverage includes keyboard/focus/text input and
composition cancellation, modal containment, deterministic virtual time,
History virtual-row reveal, and a negative control that fails when the
application's reveal request is removed.

## Windows consumer and native capture

History is an independent consumer at `c4d532534016266400f29e0bd408cf7863ce470e`,
with its Alicorn submodule pinned to `1d238ed`. Its self-test passed. Its native
smoke used the actual SDL/D3D12 host, selected a commit, presented four GPU
submissions, retired all submissions, and exited successfully.

The native diagnostic capture produced `diagnostics.json`, `inspector.txt`,
`timeline.json`, `windows.json`, `events.jsonl`, and a 1200×800 `screenshot.ppm`
at 100% display scale. The capture was made with
`--smoke --select-first --diagnostics --capture-after=0 --capture-dir=...`.
The local capture bundle is in the ignored `out/issue-165-history-capture-final`
directory; it is intentionally not committed as a machine-specific golden.

Headless replay stays CPU-only. Native screenshots remain tied to a graphics
backend, driver, and display scale; they are diagnostic artifacts rather than
universal pixel hashes. The native diagnostic path is separate from serialized
replay logs, so this work does not claim an automated cross-machine
screenshot-as-spec or documentation-image update pipeline.

## Result

The GO criteria are met: an external consumer drives its real production
callbacks through public testui APIs, the deliberate missing-reveal regression
is caught, serialized replay verifies stable semantic identity and causal/work
evidence, and CPU-only versus native-only behavior is documented. Keep
backend-specific screenshot baselines and automated screenshot-as-spec
publication as follow-up work; do not treat them as a cross-platform pixel
contract.
