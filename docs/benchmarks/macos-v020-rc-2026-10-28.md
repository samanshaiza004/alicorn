## Matched investigation

Both source snapshots were rebuilt and run on the current macOS 27.2 machine,
with the same Odin executable and compiler flags. Baseline:
`96461223cdbf43080acb957276c045ad704f4606`; candidate: `3e31c743298f758b4cafd4f425e296a59cd95e34`.
The probe uses each revision's actual `measure_regions`, `measure_tree`, and
`render_large_region` benchmark helpers, replacing only the program entry
point to omit unrelated workloads. Six fresh processes alternated the two
binaries, giving three samples per revision.

| Operation | Baseline median, default profile | Candidate median, default profile | Baseline median, `-o:speed` | Candidate median, `-o:speed` |
| --- | ---: | ---: | ---: | ---: |
| Initial 10,000-node tree | 54.395 ms | 148.403 ms | 22.244 ms | 48.448 ms |
| Unchanged root invalidation, 10,000 nodes | 21.402 ms | 42.360 ms | 8.001 ms | 15.348 ms |
| Reuse 10,000-descendant region for sibling change | 0.293 ms | 11.553 ms | 0.131 ms | 2.984 ms |

Region reuse is about **39.4× slower** in the default profile and **22.8×
slower** with optimization in this matched probe. Initial construction is
2.7× slower by default and 2.2× slower optimized. These timings concern the
headless retained workload, not a measurement of native input latency.

### Minimized reproduction and bisection

The smaller fixture warms one retained region, then changes a sibling's paint
value 100 times. The region revision stays fixed and its body executes once.
With 1,000 descendants, the baseline took 1.459–2.172 ms total and the candidate
67.853–72.691 ms. Both emit/reconcile only 300 descriptions over those 100
updates. With 10,000 descendants, the candidate took 1.049–1.072 seconds total.

A bisection through master's first-parent history isolated the first severe
step to `ac0a420c17f1c83ef283fee38da2a37fe4bfaedd`, **Add retained leaf
measurement and geometry finalization**. Its parent `927e74a55e3d` took
2.461–3.148 ms for 100 sibling updates beside 1,000 descendants; the commit
took 46.088–53.179 ms in the boundary verification.

### Identified work outside the locality counters

1. `layout_measure_retained_dirty_nodes` in
   [layout_measure.odin](../../runtime/layout_measure.odin) scans `rt.order`
   every described frame. It checks presentation ancestry and reads the
   measurement state even for clean descendants of a reused region.
2. The incremental branch in [paint.odin](../../runtime/paint.odin) updates one
   `display_target` command, then calls `layout_finalize_display`, which
   rebuilds/finalizes every command. The composition counter still reports
   one updated command. This and the measurement sweep began in `ac0a420`.
3. `adaptive_semantics_sync_descriptions` in
   [adaptive.odin](../../runtime/adaptive.odin) refreshes tree order for every
   retained node even when the description contains no adaptive alternatives.
   This later sweep was introduced in `e3f5ece`.

A stage timing probe on the candidate's 10,000-descendant, 100-update fixture
measured 462.771 ms in the measurement sweep and 368.941 ms in paint, within
1,127.925 ms total. Layout itself took 0.170 ms and semantic commit 0.005 ms.

Controlled changes to ignored diagnostic source copies confirmed causality:

| Diagnostic variant, default profile | Total for 100 updates beside 10,000 descendants |
| --- | ---: |
| Unchanged candidate | 1,114.904 ms |
| Bypass measurement sweep | 660.844 ms |
| Finalize only the changed display command | 659.018 ms |
| Bypass unconditional adaptive tree-order refresh | 799.269 ms |
| Apply all three diagnostic changes | 1.582 ms |

The bypasses are valid only for this warmed fixture: it has no dirty
measurement nodes and no adaptive alternatives. They establish where the
time goes; they are not a generally correct production patch. The tracked
runtime remains unchanged, and temporary instrumentation was removed from
the source copies after measurement.

### Implementation direction

- Schedule measurement from a deduplicated dirty-node queue. Reserve broad
  invalidation for actual font/dependency changes, and preserve constraints,
  axis propagation, and presentation activation behavior.
- Finalize the affected display slot when the incremental command index is
  stable. Keep complete finalization for structural rebuilds and scale changes,
  retaining unsnapped target geometry for repeated DPI transitions.
- Refresh accessibility tree order when adaptive semantic membership/order
  actually changes, using the existing retained order on ordinary sibling
  paint updates.
- Count examined measurement nodes, finalized display commands, and semantic
  order visits so region-locality assertions expose these costs.

The construction slowdown is also measured, but the diagnostic bypasses above
isolate warm reuse rather than fully explaining initial allocation, shaping,
measurement, and geometry setup. Those initial costs still need profiling.
